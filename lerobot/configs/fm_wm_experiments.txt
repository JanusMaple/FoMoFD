FM-WM experiment configurations
===============================

Each task has the following configuration groups:
  k_ablation_l4/             k1.yaml, k2.yaml, k3.yaml, k4.yaml, k6.yaml, k8.yaml
  l_ablation_k4/             l1.yaml, l2.yaml, l4.yaml, l6.yaml, l8.yaml
  action_ablation_k4_l4/     no_action.yaml, adaln_only.yaml,
                            cross_attention_only.yaml,
                            cross_attention_and_adaln.yaml
  data_size_ablation_k4_l4/  data33.yaml, data66.yaml, data100.yaml
  seed_ablation_k4_l4/      seed-specific repeats

K is the prediction horizon and L is the observation-history length, both in
recorded steps. The visual representation uses eight VAE latent channels per
camera. WM-NC, WM-PE, and WM-PU are scoring modes of the trained world model.
The full model uses action cross-attention and AdaLN; NoACT removes both paths.

The main configuration is flow_matching_wm.yaml: K=4, L=4, both cameras,
both action-conditioning paths, full expert training data, and seed 0. The
k4.yaml, l4.yaml, cross_attention_and_adaln.yaml, and data100.yaml references
describe this same model and share one output directory.

Checkpoints are stored under:
  fomofd/tasks/TASK/model/fm_wm/
    fm_wm_vfmfvae_z8_both_state_off_k4_l4_action_both_data100_seed0/
      config.json
      splits.json
      checkpoints/best.pt
      checkpoints/last.pt

Within each sweep, other model settings are held fixed. Maximum training steps
are 120000 for Needle Pickup, 80000 for Ring Over Post and Tissue Retraction,
and 100000 for Shunt Insertion. Use distinct run names when changing model
settings or training seeds; see model_organization.md.

Expert demonstrations are split into training/validation with val_ratio=0.1
and split_seed=0. Training-data fractions are exactly one third, two thirds,
and full, selected as nested subsets with train_subset_seed=0. They contain
75/150/225 training episodes for each simulation task and 30/60/90 for each
real task. Validation episodes, frozen VAEs, and normalization remain fixed.
This measures world-model data sensitivity with a fixed visual representation.

Train from the lerobot/ directory, for example:
  python -m models.flow_matching_wm.train --config configs/needle_pickup/k_ablation_l4/k2.yaml

Policy rollouts are used for calibration and evaluation. The task's
flow_matching_wm_score.yaml selects the policy-rollout dataset; --split all
scores all recordings. Scoring loads the saved config.json beside the
checkpoint. To inspect expert validation scores, select the expert dataset
in a scoring config and use --split val.

Sampled policy-action scoring requires stored action chunks at least as long
as K. Reactive and predictive scoring use the prepared per-frame features.
